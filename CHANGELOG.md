# Changelog

## Unreleased

## 0.1.8 - 2026-11-18

- CPython on-CPU sampling on the platforms that already have a native sampler: macOS (Apple Silicon and Intel), Windows x64, and Linux x86_64. The on-CPU events are still Mach, `StackWalk64`, and `perf_event_open`. A Python function runs inside the interpreter, so when the leaf is inside that image the user stack is the interpreter frame chain (`co_qualname`, `co_filename`, and a line from `co_linetable`) rather than the interpreter's C frames. C helpers in the same image stay on that Python stack. A leaf in another image stays native. A leaf inside the interpreter image whose frame chain cannot be read (the thread id is missing, a pointer is not plausible, or a read is short) also keeps the native walk, and those frames are not labeled `[python]`. A denied `process_vm_readv` does not take that path: `start` returns an error and no profile is written. Frames are prefixed `[python]`. The walked layouts are the default GIL builds of 3.11, 3.12, and 3.13. 3.11 keeps `use_tracing` and `wstr`, so `current_frame` is at 8 and compact ASCII data starts at 48. 3.13 reads `_Py_DebugOffsets` only when `free_threaded` is 0. CPython older than 3.11, 3.14 and later, a free-threaded build, and a 3.13 image without that table are detected and `start` returns an error instead of a native profile. PyPy is not detected. A 32-bit image is not walked. A leaf in libc or a C extension stays native. A thread blocked in `time.sleep` is off CPU. Two pure-Python threads both appear as the GIL switches. On Linux the frame read is `process_vm_readv`, which needs ptrace attach permission. `perf_event_open` permission is not enough when `kernel.yama.ptrace_scope` is 1 and the target is not a descendant: the backend returns an error that names the errno and the scope, and it does not record native eval-loop frames. anyprof does not change that sysctl. The default is 99 Hz speedscope, and an omitted `-o` writes `anyprof-python-<pid>-YYYYMMDD-HHMMSS.speedscope.json`. Other architectures compile and `start` returns not implemented.
- CI installs CPython 3.11, 3.12, and 3.13 and live-samples each one (the spin function and its caller, a thread blocked in `time.sleep`, two threads sharing the GIL while the main thread waits off CPU, and the CLI profile) on `macos-latest`, `macos-15-intel`, `windows-latest`, and `ubuntu-latest`. The busy fixture's function is `spin_é`, a non-ASCII compact string, so the read uses the compact non-ASCII offset rather than the ASCII one. Its line has to be the source line of `x = x + 1` or the `while True` jump, and `caller` has to be on the call line. Ubuntu compiles `crates/anyprof-native/tests/cpython_offsets.c` against those three header trees. It also requires the `process_vm_readv` refusal while `kernel.yama.ptrace_scope` is 1, then sets that sysctl to 0 for the frame samples. anyprof does not write it. The macOS library tests re-exec `supported::<test> --exact`. The MSRV job does not set `ANYPROF_REQUIRE_NATIVE` and does not install Python. Free-threaded builds and 3.14 are detected and refused, not sampled.

## 0.1.7 - 2026-11-18

- Go on-CPU sampling on the platforms that already have a native sampler: macOS (Apple Silicon and Intel), Windows x64, and Linux x86_64. The on-CPU events are still Mach, `StackWalk64`, and `perf_event_open`. A Go leaf often has no frame pointer (`main.spin` can be `nop; jmp`), so when the executable has a Go 1.18+ pclntab the user stack is unwound with that table’s pcsp values, the same rule as `runtime.gentraceback`. Names, files, and lines come from pclntab, including a binary built with `-ldflags=-s -w`. Go 1.18 through 1.25 store the text base in the pclntab header. Go 1.26 keeps magic `0xFFFFFFF1` and writes that word as zero; entry offsets are relative to `moduledata.text` (`runtime.text`) in `.go.module`, Mach-O `__go_module`, or the PE `.data` record. A cgo binary’s `runtime.text` is not the first byte of the text section, and that section address is not used in its place. On an externally linked Mach-O, the Go 1.22 header word and the Go 1.26 `moduledata` pointers are addends from the `__TEXT` vmaddr, plain or in the low bits of a chained fixup; the link address is the sum when it falls inside `__text`. A value already inside the text section (internal Mach-O, ELF, and PE) is kept. Go older than 1.18 is still detected from `\xff Go buildinf:` and is sampled with the native walk; the 1.2 and 1.16 pclntab layouts are not read. One executable pclntab is used. A plugin is not a second walk. Inlined callees stay inside the outer function. cgo stops at the Go function that entered C, plus that return PC. Frames are prefixed `[go]` in collapsed stacks, speedscope, and pprof. A leaf that is not a Go function keeps the native walk. Parked goroutines are not sampled: the PC and SP are the OS thread’s, which is the goroutine that thread is running, not a snapshot of every goroutine. A goroutine blocked in a syscall shows the scheduler or system stack that is actually on CPU. Auto-detection reads `\xff Go buildinf:` without attaching, on Linux (`/proc/<pid>/exe`), macOS (`proc_pidpath`), and Windows (`QueryFullProcessImageNameW`). The default is 99 Hz pprof, and an omitted `-o` writes `anyprof-go-<pid>-YYYYMMDD-HHMMSS.pb.gz`. Other architectures compile and `start` returns not implemented. Linux musl x86_64 is the same sampler; CI `cargo check`s it and does not live-sample it. The Linux user-stack copy stays 8 KiB, so a return slot past that copy ends the pcsp walk.
- CI live-samples stripped Go 1.22 and Go 1.26 programs (the spin function and its caller, a goroutine blocked in `time.Sleep`, and two goroutines locked to OS threads) on `macos-latest`, `macos-15-intel`, `windows-latest`, and `ubuntu-latest`. The fixtures are built with `go build -o <binary> .` from the canonical module directory, because an absolute `/var/folders` path is outside the module Go sees through `/private/var`. The macOS library tests re-exec `supported::<test> --exact`. The MSRV job does not set `ANYPROF_REQUIRE_NATIVE`, does not install Go, and does not change sysctls. A skipped live test is not a failure, and that job is not the sampling evidence. When `go` is already on `PATH`, the pclntab unit test parses that toolchain. On the Ubuntu 26.04 image that is Go 1.26, and the Go, C++, and Rust live tests ran.

## 0.1.6 - 2026-11-18

- Rust on-CPU sampling on the platforms that already have a native sampler: macOS (Apple Silicon and Intel), Windows x64, and Linux x86_64. There is no second sampler. `anyprof-rust` detects a Rust executable and `anyprof-native` records it. Auto-detection runs after Node and before Go, so a Rust pid is `using backend 'rust'` and an omitted `-o` writes `anyprof-rust-<pid>-YYYYMMDD-HHMMSS.pb.gz` at 99 Hz. `--backend native` on that pid still selects native. Rust frames are prefixed `[rust]` in collapsed stacks, speedscope, and pprof; C frames stay bare and kernel frames stay `[kernel]`. Legacy (`_ZN…17h<16 hex>E`) and v0 (`_R…`) names are demangled with `rustc-demangle` before Itanium C++, and the legacy hash is omitted. Mach-O's extra leading underscore is stripped. An Itanium C++ name stays native inside a Rust image. On Windows, dbghelp searches the executable's directory and is not pointed at a symbol server. An already-undecorated `crate::function` is labeled Rust when the file is a Rust image, including `{closure#0}` and `{impl#0}`. An already-undecorated generic (`foo::<T>`) or trait path (`<T as Trait>`) stays native unless the symbol is still mangled, so a C++ template is not relabeled. `main` and an MSVC `?` name stay native. When dbghelp returns no name, the PDB named by the PE CodeView record is tried, then the `.pdb` beside the image. The debug directory is read from its file offset, including when it sits past the first 1 MiB. A relative CodeView path is used only inside the executable's directory; `..` is ignored. An absolute path is still opened. Either file is applied only when its GUID matches the CodeView record, its PDB-info age is at least the image age, and its DBI age equals the image age when the PDB has one. A stale or unrelated PDB is skipped, and the address stays unnamed. With no CodeView record the sibling `.pdb` is still tried and cannot be checked. A PDB larger than 1 GiB is not parsed. At one RVA the longer symbol is kept, so a zero-length public does not shrink a procedure to 64 KiB. Put the matching PDB next to the exe.
- Detection does not attach. The last read is shortened so the scan does not pass 32 MiB. It stops at `rustc version ` (ELF `.comment`, which survives `strip` and is present for `no_std`), the standard-library panic text for `Option::unwrap` and `Result::unwrap`, the prefix `fatal runtime error:`, or `/rustc/` plus 40 hex digits plus `/library/`. Executables do not carry a `.rustc` section. Mach-O and PE objects from rustc do not contain `rustc version `; a normal std binary is recognized from the other strings. A fully stripped `no_std` Mach-O or PE with none of those strings is not auto-detected. `--backend rust` still samples it. A non-Rust file that embeds one of the strings is detected as Rust. The executable path is `/proc/<pid>/exe` on Linux, `proc_pidpath` on macOS (same user, no root), and `PROCESS_QUERY_LIMITED_INFORMATION` plus `QueryFullProcessImageNameW` on Windows. That query is not the sampler `OpenProcess` and does not enable `SeDebugPrivilege`. A missing path is not Rust, and native is tried next.
- macOS and Linux stacks are frame pointers. rustc 1.99 does not emit them at `-O0` or `-O2` unless the binary was built with `-C force-frame-pointers=yes`. Without that flag the leaf is recorded and the callers are not. Windows uses the PE unwind data rustc already emits. Permissions, self-pid refusal, and `-k` are unchanged from the native sampler: root on macOS, same user on Windows x64 and Linux x86_64, kernel frames only on Linux x86_64. Other architectures compile and `start` returns not implemented, and they do not advertise `-k`. Linux musl x86_64 is the same sampler; CI `cargo check`s it and does not live-sample it.
- CI live-samples a busy Rust program, an idle program, and two running threads on `macos-latest`, `macos-15-intel`, `windows-latest`, and `ubuntu-latest`, under the same `ANYPROF_REQUIRE_NATIVE=1` gate as the C++ fixtures. The macOS library tests re-exec `supported::<test> --exact` and require that one test to run. The stacks must contain the demangled spin function and its caller, labeled Rust. On Windows that includes the CLI profile, which must name `anyprof_rust_fixture::anyprof_rust_spin` rather than only raw addresses. The MSRV job still does not set that variable and does not change sysctls.
- Linux ELF symbol addresses follow the `PT_LOAD` whose page the kernel mapped. rustc/lld places the executable segment 0x820 bytes into a page, and that page's file offset still falls inside the previous segment's `p_filesz`. Matching the first containing segment shifted every symbol in a Rust binary by one page, so a spin loop was named as unrelated standard-library functions. C and C++ binaries whose `p_offset` is already page-aligned resolve as before.

## 0.1.5 - 2026-11-17

- Native C/C++ on-CPU sampling on Linux x86_64. `anyprof rec -p <pid>` opens one `perf_event_open` task-clock event per thread. The counter only ticks while that thread is scheduled, so the process is not suspended and sampling anyprof's own pid is allowed. Without `-k`, kernel samples are excluded, so time spent inside the kernel contributes nothing. User stacks walk frame pointers in the sampled stack copy. At `-O2`, GCC and Clang both need `-mno-omit-leaf-frame-pointer` as well as `-fno-omit-frame-pointer`; the CI fixtures are `-O0`, where GCC still emits the leaf frame. ELF symbols, including Itanium C++ names, come from the file named in `/proc/<pid>/maps`. `-k` also records kernel frames when `kernel.perf_event_paranoid` is 1 or lower and `/proc/kallsyms` is readable. A paranoid value of 3 or 4 and another user's process are refused, and the error also reports `ptrace_scope` when that sysctl can be read. Scope 1 does not block `perf_event_open` of a same-user process: the syscall uses a read check, and Yama applies the scope to ptrace attach. anyprof does not change these sysctls. When a thread exits, its ring is drained before the mapping is dropped. A reused tid is a new thread: the old ring is drained and a new event is opened. The ring size is a power of two the kernel accepts (8 data pages under the usual 512 KiB `perf_event_mlock_kb`, not 15). Builds that are not x86_64 still return not implemented, and they do not advertise `kernel_frames` or `-k`.
- Native C/C++ on-CPU sampling on Windows x64. A tick reads `NtQuerySystemInformation` and suspends only threads in the Running state. `StackWalk64` walks that thread, then `ResumeThread` runs from `Drop` and is retried. A resume that still fails aborts the profile. The sampler does not call `SetThreadContext` or `WriteProcessMemory`. Sampling anyprof's own pid is refused before `OpenProcess`. A same-user process needs no administrator token. Another user needs `SeDebugPrivilege`. A protected process is reported separately, and anyprof does not change that protection. `IsWow64Process2` refuses 32-bit and ARM64 processes. `IsWow64Process` alone cannot see ARM64. An x64 process emulated on ARM64 reports AMD64 and is not refused. A program counter in kernel space is not stored as a user frame; later user addresses in that walk are kept. `-k` is ignored. Non-x64 Windows builds still return not implemented.
- CI samples native processes on the hosts that have a sampler. `ubuntu-latest` (x86_64) sets `kernel.perf_event_paranoid=1` and `kernel.kptr_restrict=0`, then live-samples a busy C++ program, an idle `pause()`, two running threads, an unrelated same-user process, and a tight `/dev/zero` `read` with `-k`. That read stays on CPU. `windows-latest` (x64) live-samples a busy C++ program and an idle `Sleep` and checks the self-pid refusal. `macos-latest` (arm64) and `macos-15-intel` (x86_64) live-sample a busy program and an idle program under sudo. `ANYPROF_REQUIRE_NATIVE=1` on those jobs, so a skip is a failure. aarch64 Linux is not a CI target. The MSRV job does not set that variable and does not change sysctls.
- Linux x86_64 musl compiles again. Enabling and disabling a perf event passes `libc::Ioctl`, which is `c_int` on musl and `c_ulong` on glibc. The Ubuntu CI job `cargo check`s the workspace for `x86_64-unknown-linux-musl`. That check does not build the release archives.

## 0.1.4 - 2026-11-17

- Native C/C++ on-CPU sampling on macOS. `anyprof rec -p <pid>` attaches with Mach `task_for_pid` (root), walks frame pointers, and resolves Mach-O symbols, including Itanium C++ names. The default is still 99 Hz pprof. A tick with no thread in `TH_STATE_RUNNING` records nothing. Sampling anyprof's own pid is refused before attach. `thread_resume` is retried, and a failure that might leave a target thread suspended does not return a profile. A `task_threads` list whose size is known is released. A list too large to sample ends the recording, and the message says the profile stopped. Return addresses lose one byte before symbol lookup; the leaf program counter does not. Register pointers follow Darwin's strip flags (`xpaci` / `xpacd` on Apple Silicon) and are not authenticated. Saved frame pointers and return addresses are stripped even when those registers are already raw, so an arm64 process inside an arm64e system function is not cut off. sudo does not override System Integrity Protection or a hardened runtime.
- CI live-samples a busy C++ program and an idle program on Apple Silicon (`macos-latest`, arm64) and Intel macOS (`macos-15-intel`, x86_64). The arm64 job also runs `xpaci` and `xpacd` on an unsigned pointer. It does not execute a signed arm64e stack. Windows and Ubuntu compile the native crate and check that sampling returns not implemented. They do not sample a process.

## 0.1.3 - 2026-10-22

- `anyprof view <file>` (alias `v`) opens a `.cpuprofile`, pprof, speedscope JSON, or collapsed-stacks file in speedscope 1.25.0, which is built into the binary and served on `127.0.0.1` under a random 128-bit token path. Nothing is downloaded. `record -w` / `--web` writes the profile as usual, then opens it the same way. `--no-open` prints the URL instead, `--port` picks the port, and `--web-timeout` stops the viewer after a while; otherwise it serves until Ctrl+C. Over SSH or without a display, anyprof prints the URL and an `ssh -L` port-forward command instead of opening a browser. The binary is about 0.8 MiB larger. Release archives include the speedscope (MIT) and Source Code Pro (OFL-1.1) licenses.
- `-F` above 1000000 Hz is rejected with a clear message. It used to print a `0us` sampling banner while V8 sampled every 1us.
- The idle warning shows its percentage with one decimal and never rounds a share above 95% down to `95%`.
- Node's `-v` log reports the V8 sample count in `samples`, not the total of microsecond weights.
- The minimum supported Rust version is 1.88, up from 1.85. The `anyprof update` dependencies (axoupdater and the crates it pulls in) need 1.88, so 0.1.2 did not build on 1.85. A new `msrv` CI job builds and tests the whole workspace on Rust 1.88.
- `record --help` says `-F` accepts 1..=1000000 Hz.
- A second Ctrl+C while the viewer is running exits immediately, even when a response write is stuck on a client that stopped reading. The first Ctrl+C still stops the viewer cleanly, the same as in `record`.
- The headless Chrome smoke test saves a screenshot and a text report (page state, console, DevTools log, DOM, viewer output) before it fails on a load timeout.

## 0.1.2

- Node and browser recordings sample every 100us (10 kHz) by default, the same rate as a Chrome DevTools Performance recording. The old 99 Hz default (a 10101us V8 interval) took about 80 times fewer samples and missed short request handling on a mostly idle server. Go and native keep 99 Hz. An explicit `-F` still wins, and `record` prints the rate it uses.
- `record --interval <DURATION>` sets the time between samples (`100us`, `1ms`, ...) as an alternative to `-F`. The two cannot be combined.
- `record` warns on stderr when more than 95% of samples are `(idle)` or `(program)` and fewer than 100 samples caught JavaScript, native code, or GC, and suggests recording while the process is under load. The zero-sample warning is unchanged. The final `wrote N samples` line counts V8 samples; for `.cpuprofile` recordings it used to print microseconds.
- Negative V8 `timeDeltas` no longer shift later samples onto the wrong weights when importing a `.cpuprofile`.
- `anyprof update` only installs releases from `github.com/anyprofiler/anyprof`. It refuses a receipt that names another repository and ignores the installer's host override variables and `ANYPROF_CLI_INSTALL_DIR`.
- `anyprof update` says when this binary is newer than the latest release, instead of calling it the latest.
- On Windows, leaving the old `anyprof.exe.previous.exe` behind is a warning, not a failure, since the new binary is already in place. The warning names the path from before the rename. Once the installer starts, Ctrl+C waits for it to exit so a failed install can restore the old `anyprof.exe`.
- Clearer `anyprof update` errors: install-location lookups are no longer reported as failed replacements, and the reinstall hint labels the macOS/Linux and Windows commands.
- `uptate` still works but no longer appears in `--help`.

## 0.1.1

- Node and browser recordings write the original V8 `.cpuprofile` from `Profiler.stop`, so Chrome DevTools shows a real profile. `convert` rebuilds a DevTools-valid tree (a `(root)` node, `scriptId`, linked children, and `timeDeltas` the same length as `samples`, with `hitCount` omitted). Before sampling, anyprof reads `process.pid` and refuses an inspector that belongs to a different process.
- `-o` is optional. Omitting it, or passing a directory, `.`, `..`, or a trailing separator, writes an auto-named file (`anyprof-<backend>-<pid-or-tab>-YYYYMMDD-HHMMSS.<ext>`). A leading `~` expands to the home directory. Each backend defaults to its ecosystem format: cpuprofile for Node and browser, pprof for Go and native. An explicit `--format` or output-file extension still wins.
- Short flags (`rec -p -d -f -F -b -i -t -B -k`, `conv -i -o -f -t`) and the `rec` / `conv` aliases. `-d` has no default. Ctrl+C, SIGTERM, and Windows Ctrl+Break end sampling and still save the profile. A second interrupt while the profile is being saved exits immediately.
- `anyprof update` upgrades a release-installer install to the latest GitHub Release. `upgrade` and `uptate` are aliases. If this copy is already current, the command says so and exits 0.
